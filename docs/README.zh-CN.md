# Nested-RSI

**Local Improvement Loops, Global System Evolution**

**局部改进闭环，全局系统演化。**

Nested-RSI 探索 **RSI within RSI（RSI 中嵌套 RSI）**：外层协调数据、执行框架与模型的改进，内部算子则可以通过执行反馈运行自己的局部改进闭环。局部过程产生候选数据、harness 或模型；经过外层评估接收的系统更新，才成为下一轮全局迭代的起点。

**当前发布：v1 / 0.1.0，核心代码预览。项目持续更新中。** 完整的嵌套改进流程及训练集成仍在整理发布。当前公开代码提供调度、配对评估、重复确认和离线示例。

## RSI 中的 RSI

改进算子不必是一次固定操作：为了产生更好的候选，它内部也可以通过反馈调整自身的改进过程。项目将这一思想分为三个层次：

| 层次 | 核心问题 | 更新对象 |
| --- | --- | --- |
| 算子内部的局部闭环 | 这次改进如何产生更好的候选？ | 执行支持、候选构建过程及经过验证的局部产物 |
| 外层系统循环 | 下一步尝试什么、继承什么？ | 已接受的数据池、harness、模型与训练配置 |
| 改进规则更新 | 历史经验能否让下一轮改进更有效？ | 算子提案规则与实验调度策略，需要另行验证 |

外层协调 **Data-RSI、Harness-RSI 和 Model-RSI**。以 Data-RSI 为例，内部可以先由当前 student 生成轨迹，根据失败反馈调整 harness，再对尚未解决的任务引入 teacher 辅助。经过验证的经验用于构建 student 候选，通过外层评估后才被继承。这体现了局部反馈闭环如何服务于全局系统演化。

这里的“嵌套”首先描述架构，单纯执行多阶段重试并不等于已经证明递归进步。更强的研究目标是检验：继承下来的状态或规则，是否让后续改进变得更有效。

## 三种不同的接收决定

- **轨迹入池：** 样本通过执行与质量检查，成为可用训练经验。
- **系统接收：** 候选通过外层比较，成为后续迭代的正式状态。
- **规则接收：** 新提案规则或调度策略通过独立的同起点新旧规则对照后，才被采用。

局部成功不能跳过全局评估；自适应选择结果也不能代替独立测试。当前预览不宣称每个算子都已具备同等完整的内部循环，也不宣称已经验证了持续递归收益。

## 快速运行

Python 3.10+，在仓库根目录执行。为保持 v1 兼容性，Python 导入名 `triad_rsi` 和命令 `triad-rsi-demo` 暂时沿用原名；项目及仓库名称已改为 Nested-RSI。

```bash
git clone https://github.com/boringKey/Nested-RSI.git
cd Nested-RSI
python -m venv .venv
source .venv/bin/activate
python -m pip install .
triad-rsi-demo --output artifacts/demo
python -m unittest discover -s tests -v
```

示例无需 API key 或 GPU，使用固定合成结果演示调度、重复评估与接受/拒绝，不调用真实模型、不训练，也不代表 benchmark 成绩或持续学习效果。
