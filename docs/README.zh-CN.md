# Nested-RSI

**Local Improvement Loops, Global System Evolution**

**局部改进闭环，全局系统演化。**

Nested-RSI 探索 **RSI within RSI（RSI 中嵌套 RSI）**：外层协调数据、执行框架与模型的改进，内部算子则可以通过执行反馈运行自己的局部改进闭环。局部过程产生候选数据、harness 或模型；经过外层评估接收的系统更新，才成为下一轮全局迭代的起点。

**当前发布：v1 / 0.1.0，核心代码预览。项目持续更新中。** 下文介绍的 Data-RSI 内部流程来自研究原型，完整实现及训练集成仍在整理发布。当前公开代码提供调度、配对评估、重复确认和离线示例。

## RSI 中的 RSI

一次“改进数据”的任务，内部也可能需要先改进产生数据的方法。项目将这一思想分为三个层次：

| 层次 | 核心问题 | 更新对象 |
| --- | --- | --- |
| 算子内部的局部闭环 | 这次改进如何产生更好的候选？ | 执行支持、候选构建过程及经过验证的局部产物 |
| 外层系统循环 | 下一步尝试什么、继承什么？ | 已接受的数据池、harness、模型与训练配置 |
| 改进规则更新 | 历史经验能否让下一轮改进更有效？ | 算子提案规则与实验调度策略，需要另行验证 |

外层协调 Data-RSI、Harness-RSI 和 Model-RSI；Data-RSI 是内部嵌套局部闭环的具体实例。这里的“嵌套”首先描述架构，单纯执行多阶段重试并不等于已经证明递归进步。更强的研究目标是检验：继承下来的状态或规则，是否让后续改进变得更有效。

## Data-RSI：为了生成更好的数据，先改进数据生产过程

原型以当前 student 的失败为起点，在改进任务上进行有预算约束的反馈迭代：

| 阶段 | 具体过程 | 如何利用反馈 |
| --- | --- | --- |
| Student 自主执行 | 使用当前 student 和现有 harness 执行任务 | 保留通过验证的轨迹，定位尚未解决的任务 |
| Harness 辅助 student | 根据失败提出局部指导方案，在匹配的任务与种子上做配对比较 | 选择有帮助的执行支持，记录失败提案与退步 |
| Teacher 辅助 | 对 student 仍无法可靠完成的目标，使用所选 harness 调用 teacher | 验证示范轨迹；不因为来自 teacher 就自动入池 |
| Teacher 侧 harness 修正 | 配置允许且 teacher 仍失败时，根据 teacher 的失败反馈再提出局部 harness 修正 | 在有界预算内配对验证，保留成功任务作为对照 |
| 回到外层循环 | 将符合条件的经验加入训练池，训练 student 候选 | 与当前已接受状态比较，通过外层接收判定后才继承 |

这是按失败情况逐步升级的过程，不要求每个任务都经过全部阶段。内部的 harness 提案可能被拒绝，teacher 侧修正也受配置和预算限制。

关键区别是：**局部 harness 有帮助，不意味着它自动成为正式部署版本；单条轨迹有效，也不意味着整个候选系统已经改善。** 即使一个 harness 在整体比较中未被选中，它产生的个别轨迹仍可在通过质量检查后被保留。训练出来的 student 依然必须通过外层评估。

接受后的 student 会参与后续数据构建，进而改变下一轮的能力边界与辅助需求。这种相互作用是否带来持续收益和更高的数据效率，需要通过实验验证。

## 三种不同的接收决定

- **轨迹入池：** 样本通过执行与质量检查，成为可用训练经验。
- **系统接收：** 候选通过外层比较，成为后续迭代的正式状态。
- **规则接收：** 新提案规则或调度策略通过独立的同起点新旧规则对照后，才被采用。

局部成功不能跳过全局评估；自适应选择结果也不能代替独立测试。当前预览不宣称每个算子都已具备同等完整的内部循环，也不宣称已经验证了持续递归收益。

## 快速运行

Python 3.10+，在仓库根目录执行。为保持 v1 兼容性，Python 导入名 `triad_rsi` 和命令 `triad-rsi-demo` 暂时沿用原名；项目及仓库名称已改为 Nested-RSI。

```bash
git clone https://github.com/boringKey/Nested-RSI.git
cd Nested-RSI
python -m venv .venv
source .venv/bin/activate
python -m pip install .
triad-rsi-demo --output artifacts/demo
python -m unittest discover -s tests -v
```

示例无需 API key 或 GPU，使用固定合成结果演示调度、重复评估与接受/拒绝，不调用真实模型、不训练，也不代表 benchmark 成绩或持续学习效果。
